# ADR 0002：本地监听与按需 GPT-Live 会话

- 日期：2026-09-10
- 状态：自动模式已由[服务端语音控制](../server-voice-control.md)取代；按住说话和冷启动录音交接仍适用。以下保留原决策记录。
- 取代：ADR 0001 中“首版保持 Live 全程连接”的决策

## 决策

用户开启语音后，浏览器只启动本地麦克风与 AudioWorklet，不创建 GPT-Live 会话，不向云端发送环境音。保留短暂的 PCM 环形缓存。检测到超过阈值的持续发言，立即暂停播客，冻结恢复点，并建立云端连接。

连接冷启动时，持续缓存第一段提问。检测到发言结束后，将含预录的 WAV 交给后端转录；同时等待 Live 的 `session.started`。两个条件均满足且问题版本仍有效时，将用户完整文本交给现有工具问答后端，结果通过 `session.commentary.append` 返回 Live。首句不是通过 WebRTC 补发音频；连接启动时克隆的麦克风轨道禁用，只发送静音，避免部分首句与转录重复触发回答。

后续问题直接走已建立的实时语音会话。再次建连时，使用应用保存的近期用户/助手文本恢复上下文。节目当前位置继续通过上下文通道同步。

## 生命周期

```text
关闭 → 开启本地监听（无 Live）
     → 检测到提问 → 暂停节目、缓存首句、建立 Live
     → 首句转录完成 + 会话就绪 → 工具问答与实时追问
     → 用户明确继续 → 自然起点播放 → 保留 5 秒 → 关闭 Live
     → 继续本地监听
```

- 保留期内追问取消关闭倒计时，复用同一连接。
- 无发言、无 AI 输出、无后端工作时，60 秒后关闭 Live，但不恢复播客。
- 关闭仅释放云端拥有的克隆轨道，保留本地采集。用户关闭语音或离开页面才释放本地麦克风。
- 首句录音上限 60 秒，达到上限停止采集并提示；关闭语音清除内存缓存。
- 新发言使旧转录和问答版本失效。冷启动期间补充内容继续保留在同一录音中；下一次转录使用完整内容。
- 用户提前选择继续、手动定位或输入文字时，取消过期首句转录，防止迟到回答打断已经恢复的节目。
- 云端关闭后才启动下一条云端连接，避免关闭交接期间同时保持两条付费连接。
- `session.close` 后等待 `session.closed`；超时标记最终用量未确认。逐会话保存累计用量，重复事件不重复计数。

## 配置

根目录 `.env`，后端校验并通过明确白名单下发非敏感参数：

```dotenv
ASIDE_MIC_THRESHOLD=0.025
ASIDE_MIC_MIN_SPEECH_MS=120
ASIDE_MIC_SILENCE_MS=650
ASIDE_MIC_PRE_ROLL_MS=750
ASIDE_LIVE_GRACE_MS=5000
ASIDE_LIVE_IDLE_CLOSE_MS=60000
```

实际预录长度至少覆盖语音触发所需持续时间加 80 毫秒，避免用户调高触发时长后截掉首字。计时在浏览器本地，不依赖服务器往返。修改后重启后端并刷新页面。

## 代码边界

- `frontend/src/microphone-buffer.ts`：PCM 环形缓存、语音活动检测和 WAV 编码，无网络。
- `frontend/src/microphone.ts`、`frontend/public/microphone-worklet.js`：本地浏览器采集。
- `frontend/src/on-demand-voice.ts`：按需生命周期、首句交接、过期结果和关闭策略。
- `frontend/src/live.ts`：WebRTC 克隆轨道、事件、输出控制、会话就绪与关闭。
- `backend/src/app.ts`：受限的首句 WAV 转录端点与逐会话用量接口。
- `backend/src/provider.ts`：真实转录、Live 会话初始化与历史恢复。
- engine 的节目播放状态机和语义恢复算法继续复用。

## 成本与验证边界

本地监听不产生 Live 会话时长费用；首句转录、实际语音会话和后端推理/检索仍产生费用。WebRTC 初始化有计费规则，噪音误触发仍可能产生费用，不能以请求次数或墙钟推断实际账单。

已用测试替身验证连接按需建立、双条件交接、补充提问、保留期取消、闲置关闭和首句取消。浏览器测试使用本地合成输入，实际运行 AudioWorklet 和 WAV 编码；云端请求被测试拦截，不调用付费模型。真实 GPT-Live 首次响应延迟、中文转录准确率、输出静音判定和节省比例需另外验证。

## 2026-09-10 更新：回答后自动续播

用户明确改为回答结束后 3 秒无输入即继续，替代此前必须明确说继续的交互。`ASIDE_AUTO_RESUME_MS` 默认 3000，0 禁用。由前端在回答音频结束后计时，不由模型判断；等待工具结果、用户发言、输入文字、断线、关闭语音、换集或手动操作时不触发。重用自然恢复点与版本校验，超时自动恢复不再额外等待手动恢复的 1 秒。音频结束仍由现有 900ms 静音检测估计，无法视为精确的服务端结束信号。

## 2026-09-10 更新：播放与麦克风联动

手动开始播放同步请求麦克风权限并开启本地监听；手动暂停、播放结束或换集关闭麦克风并取消待处理回答。Agent 插话暂停与自动续播维持麦克风。主播放按钮在问答期间仍表示手动暂停整个收听会话；继续听按钮返回节目。麦克风显示为状态，不再要求单独开启。权限失败时显示错误，仍允许原音频播放。开始监听不创建云端会话，首次实际发言才建连。

## 2026-09-10 更新：明确继续指令

明确继续指令确认后 1500ms 回到原自然断点，立即静音 Agent，期间新发言撤销恢复。计时不包含冷启动转录/识别耗时。热会话同时监听用户转录与委派事件，不要求模型先委派才处理 continue/go on。常见完整句走本地保守匹配（含礼貌前后缀），解释请求、否定、引用与临时改口不走快捷路径；其余自然表达通过后端 resume_podcast 工具做语义判断，有歧义时要求澄清。自动 3 秒续播、手动按钮和明确语音指令分别保留各自等待时间。
